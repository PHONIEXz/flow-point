# Flow Point: measured-usefulness pilot

Prepared 22 October 2026. Status: protocol ready; no human timing results collected.

This is a small formative comparison, not a controlled productivity study. Generation latency and agent test times are not human time-savings measurements.

## What to measure

Can an organizer produce a correct, usable event preparation pack with less elapsed time using Flow Point than with their normal manual tools?

Participant P1: Phoenix, project owner. Describe this relationship when reporting results. Do not put private participant contact information in this public file. One participant and three tasks support only a small personal pilot.

## Setup

- Use the same device, connection and workspace for both methods.
- Before timing, read these instructions and try Flow Point's sample once. Record prior experience.
- Manual method: usual text editor and spreadsheet/calculator; no generative AI, ready-made event pack or previous trial output.
- Assisted method: Flow Point; editing, clarifications and retries are allowed and count.
- Open the required tools before starting. For the initial comparison, load Flow Point until its workspace is ready and record that this was a warm-service test. Record any later provider delays or failures. A separate cold-start run can be reported separately.
- Use the same brief for each method. Start each attempt with an empty document/workspace. Keep completed outputs closed while doing the other method.
- Suggested order: school manual then assisted; church assisted then manual; community manual then assisted. Record the actual order. Reusing a brief can make the second attempt faster; alternating order only partly addresses this. Acknowledge learning bias.
- Take a short break between attempts. Run when ready; do not estimate a baseline from memory.

## Timing rule

Start the stopwatch when you begin reading the event brief. Stop only after all four outputs are checked and the pack and budget files are saved.

Primary measure: total elapsed seconds, including reading, typing, generation waits, corrections, review, retries and exports. Keep provider waits in the result. For unrelated interruptions, pause the stopwatch and separately log the interruption duration/reason. Do not subtract normal work or waiting.

Optionally measure hands-on time with a second timer/observer; leave it blank if it cannot be measured reliably. Never label total elapsed time as hands-on time.

If an attempt is abandoned or exceeds 15 minutes, record the elapsed time and "incomplete", with the reason. Do not substitute zero, exclude a slow failed attempt silently or calculate savings for an incomplete pair. Keep any later retry as a separate attempt.

## Required outputs for each attempt

1. A clear invitation of roughly 80–150 words containing the event, correct date/time/venue, organizer and signatory.
2. A proposed schedule with at least five entries, ordered within the supplied event window.
3. At least six useful preparation tasks. Do not invent named owners or deadlines; these may remain unassigned.
4. A budget with all three supplied items, quantities, unit prices and correct total in NGN.

Manual files: save a text/Markdown pack and a budget CSV using normal editor/spreadsheet tools. Assisted files: download Flow Point's Markdown pack and Budget CSV after review/approval. Word-for-word identical prose is not required. Both outputs must reach the same acceptance standard.

## Quality gate: apply equally to both methods

Mark each item pass/fail; fix failures before stopping the clock, or mark the attempt incomplete. The participant may self-check for the pilot. If possible, have a second person check the saved outputs without seeing timings.

- All event facts match the brief: title, weekday/date, start/end time, venue, organizer and signatory.
- Invitation is usable, meets the approximate length target, and contains no unresolved placeholders.
- Schedule has at least five chronological entries within the event window, with no conflicting date/time.
- Checklist has at least six relevant preparation tasks and no invented confirmed bookings, named owners or dates.
- Budget contains exactly the three requested items, correct quantities, unit prices and NGN total.
- Both files open and have readable content, currency/amounts and all requested sections. No draft/sample labeling remains in the finished assisted pack.

Count factual/arithmetical/omission corrections, not every keystroke or stylistic rewording. One wrong fact repeated in both invitation and schedule counts as one correction, with both locations recorded. Also record generations, retries, unresolved questions and failures.

## Calculations after complete pairs exist

For each task:
- Saved seconds = manual elapsed seconds − assisted elapsed seconds.
- Reduction (%) = 100 × (manual − assisted) / manual.
- A negative result means Flow Point took longer.
- Only calculate when manual elapsed is greater than zero and both attempts pass quality.

Report each paired result, completion counts, and the participant/task count. With three complete pairs, the overall aggregate reduction is 100 × (sum of manual elapsed − sum of assisted elapsed) / sum of manual elapsed. Do not call this the mean of the three percentages; they are different calculations.

Any public claim must identify this as a self-test by the project owner, disclose order and learning bias, include review/export time, identify failures, and avoid generalizing to all organizers.
