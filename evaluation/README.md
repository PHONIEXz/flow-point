# Quality evaluation v1

Ten fictional paired briefs and updates: four exposed regressions, six fresh before first inference. The assistant wrote and checked expectations before generation. This is not independent/blinded adjudication. `freeze-v1.json` hashes the cases, provider/validation implementation, application history helpers, scorer and runner. No prompt tuning is permitted during this run. After tuning on outputs, use a new unseen set.

Run `node scripts/evaluate-quality.mjs --live` to make real hosted calls, or omit `--live` for a dry run in `tmp/quality-dry-run`. Live records default to `docs/evidence/quality-v1-2026-10-24/`. Every completed/failed operation is saved separately with original stage replies, request IDs and diagnostics. Interrupted records are archived before a later attempt. Finished records are reused rather than silently retried. Update is skipped when its Prepare fails; the planned operation remains in the denominator. HTTP 429 stops further inference. Client pacing uses at most 24 generation requests per fixed ten-minute bucket, leaving capacity for the owner; it does not bypass server/provider quotas.

The scorer checks declared structured facts, explicit unknowns, canonical budget labels/quantities/prices, totals/allowance, named duties, rehearsal dates, required questions, literal venue/signer/start in drafts, supplied programme times/durations and untrusted text exclusion. It distinguishes correct, missing, wrong, invented-for-explicit-unknown, unverified extras and cases needing manual review. Reworded task labels or alternative correct schedule formatting can create false negatives; an exact literal pass does not prove all content is correct. Source-warning counts distinguish an unsupported/missing/manual source state from a generic requirement to review the pack. No confidence or overall reliability percentage is inferred.

Raw model updates and application-applied updates are scored separately. Application history retains omitted questions for review; it does not claim those questions are answered. Exports exercise all four individual PDFs, and approval is probed only for structurally valid packs that still have review issues. The test never supplies approval on a clean pack as a substitute for human review. PDF headers and download responses prove protocol behavior, not visual layout; PDF visual QA is separate.

The fixed worksheet baseline is filled from the frozen answer key and preserves known facts, unknowns and arithmetic in a simple table. It does not extract source notes or provide prose documents. It is a presentation/arithmetic reference, not a fair extraction competitor or timed human baseline. Manual drafting/review/export effort is unmeasured.
